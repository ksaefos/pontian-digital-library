# Ποντιακή Ψηφιακή Βιβλιοθήκη — έκδοση 2.1.2

**ΕΝΙΑΙΟ README — Εγκατάσταση, χρήση, ασφάλεια και αλλαγές.** Το παρόν αντικαθιστά τα προηγούμενα, διάσπαρτα αρχεία οδηγιών.


## Έκδοση 2.1.2 — Διορθώσεις διάταξης κινητού

- Αρχική βιβλιοθήκη: καταργήθηκε η ανεπιθύμητη οριζόντια κύλιση. Τα στοιχεία, οι κάρτες και οι εικόνες περιορίζονται στο διαθέσιμο πλάτος οθόνης και τα μεγάλα κείμενα αναδιπλώνονται.
- Reader σε **πλήρη προβολή (immersive)**: ο χώρος σελιδοποίησης καταλαμβάνει όλο το διαθέσιμο πλάτος του κινητού, χωρίς εξωτερικά περιθώρια, περιμετρική σκιά ή γραμμή πλαισίου. Το φόντο και η σελίδα χρησιμοποιούν την ίδια μεταβλητή χρώματος χαρτιού σε φωτεινή, σέπια και νυχτερινή προβολή.
- Τα εσωτερικά περιθώρια κειμένου παραμένουν ώστε να μην ακουμπά η γραφή στις ακμές.
- Η σκόπιμα σμικρυμένη προβολή κατά την εμφάνιση των χειριστηρίων διατηρείται. Desktop, swipe, popups, double tap, βιβλία, Studio και Worker παραμένουν αμετάβλητα.
- Το πιθανό στιγμιαίο τρεμόπαιγμα κατά το animation του OpenPageFlip **δεν έχει αντιμετωπιστεί στην παρούσα έκδοση**, επειδή χρειάζεται αναπαραγωγή σε πραγματική συσκευή και έλεγχο της συγκεκριμένης ακολουθίας frames.
- Επικαιροποιήθηκε η PWA cache.

### Αναβάθμιση από 2.1.1

Στο ίδιο repository και branch `main` αντικατάστησε **μόνο** τα `index.html`, `sw.js` και `README.md`. **Μην ανεβάσεις το `library-data.json` του πακέτου**, επειδή η τρέχουσα βιβλιοθήκη ενημερώνεται μέσω Studio/Worker. Μετά το GitHub Pages deployment κλείσε και άνοιξε ξανά την PWA, ώστε να ενεργοποιηθεί ο νέος Service Worker.

Η διάταξη ελέγχθηκε σε επίπεδο CSS/σύνταξης. Απαιτείται οπτική επιβεβαίωση σε πραγματικό κινητό.

## Έκδοση 2.1.1 — Ευχρηστία ανάγνωσης στο κινητό

- OpenPageFlip: μικρότερη απαιτούμενη απόσταση swipe (18 CSS px αντί 30) και συντομότερο animation (480 ms αντί 650 ms) **μόνο στο κινητό**.
- Εφεδρική σελιδοποίηση: όριο οριζόντιας κίνησης 32 px αντί 52 px. Διατηρείται ο έλεγχος κατεύθυνσης και η προστασία χειρονομιών συστήματος στις άκρες.
- Αναδυόμενες επεξηγήσεις γλωσσαρίου: αυτόματη απόκρυψη μετά από 6–25 δευτερόλεπτα, ανάλογα με το μήκος (65 ms/χαρακτήρα). Η αλληλεπίδραση παγώνει το χρονόμετρο και το κλείσιμο με άγγιγμα εκτός εξακολουθεί να λειτουργεί.
- Αναδυόμενες επεξηγήσεις εκφράσεων: 8 δευτερόλεπτα αντί 3,5.
- Το παρατεταμένο άγγιγμα 350 ms και η διακριτή ενέργεια double tap για το μενού **παραμένουν αμετάβλητα**.
- Καμία τροποποίηση σε `library-data.json`, `admin.html`, `admin.js` ή Cloudflare Worker.
- Ανανεώθηκε το όνομα PWA cache για να ληφθεί ο νέος Reader.

### Αναβάθμιση από 2.1.0

Για τη συγκεκριμένη μικρή αναβάθμιση αντικατάστησε στο **ίδιο branch** μόνο `index.html`, `sw.js` και `README.md`. Τα υπόλοιπα αρχεία δεν χρειάζονται αντικατάσταση. Μην αντικαταστήσεις το δυναμικά ενημερωμένο `library-data.json` με το αντίγραφο μέσα σε παλιό ZIP. Μετά το GitHub Pages deployment ανανέωσε τον Reader· εάν είναι εγκατεστημένος ως PWA, κλείσε και άνοιξέ τον ξανά για να ενεργοποιηθεί ο νέος Service Worker.

Η πρακτική αίσθηση της αφής πρέπει να ελεγχθεί σε πραγματική συσκευή, καθώς δεν μπορεί να διαπιστωθεί μόνο με συντακτικό έλεγχο.

## 1. Τι περιλαμβάνει

- `index.html`: δημόσια εφαρμογή ανάγνωσης.
- `library-data.json`: **το πλήρες περιεχόμενο** (βιβλία, κεφάλαια και γλωσσάρι). Είναι η πηγή αλήθειας της δημοσιευμένης βιβλιοθήκης.
- `admin.html`, `admin.js`: καινούρια βασική διαδικτυακή σελίδα διαχείρισης.
- `cloudflare-worker.js`: πηγαίος κώδικας για τον Cloudflare Worker — **όχι** αρχείο που εκτελείται από το GitHub Pages.
- `sw.js`, `manifest.webmanifest`, `icons/`, `vendor/`, `PontianDL_Logo.svg`: PWA, εικονίδια, βιβλιοθήκη ξεφυλλίσματος και λογότυπο.
- `README.md`: αυτός ο οδηγός.

Η 2.1.0 βασίζεται στην 2.0.7. Προσθέτει διαχείριση μέσω Worker/GitHub και το προαιρετικό πεδίο `publicationYear` στα βιβλία. Οι υπάρχουσες εγγραφές διατηρούνται. Η ενσωματωμένη νέα διαχείριση είναι **βασική** και δεν υποκαθιστά απαραίτητα όλες τις δυνατότητες του αυτοτελούς Library Studio 0.8.7.

## 2. Αντίγραφο ασφαλείας (μία φορά πριν από τις αλλαγές)

Αν έχεις ήδη κατεβάσει και κρατήσει ολόκληρο το προηγούμενο repository/ZIP (π.χ. 2.0.7), **δεν χρειάζεται νέο backup**. Μην διαγράψεις το υπάρχον αποθετήριο.

## 3. Ανέβασμα στο GitHub — στο ΙΔΙΟ repository και ΙΔΙΟ branch

**Ναι: ανεβάζεις στο ίδιο branch (`main`, εφόσον αυτό χρησιμοποιούσες). Δεν χρειάζεται νέο branch, νέο repository ή ξεχωριστό deployment.**

1. Κατέβασε το ZIP της 2.1.0 και αποσυμπίεσέ το.
2. Άνοιξε στο GitHub το **υπάρχον repository** και έλεγξε ότι έχεις επιλέξει το ίδιο branch με πριν (συνήθως `main`).
3. Επέλεξε **Add file → Upload files**. Ανέβασε τα αρχεία από το εσωτερικό του αποσυμπιεσμένου πακέτου, **όχι το ίδιο το ZIP και όχι έναν επιπλέον περιβάλλοντα φάκελο**. Διατήρησε τις διαδρομές `icons/` και `vendor/`.
4. Επίτρεψε την αντικατάσταση των αρχείων με ίδια ονόματα (`index.html`, `library-data.json`, `sw.js` κ.λπ.) και την προσθήκη των νέων (`admin.html`, `admin.js`, `README.md`, `cloudflare-worker.js`). Μη διαγράψεις άλλα αρχεία που ήδη υπάρχουν.
5. Γράψε μήνυμα commit `Pontian Digital Library v2.1.0` και πάτησε **Commit changes**.
6. Άνοιξε την ήδη χρησιμοποιούμενη διεύθυνση GitHub Pages. Επαλήθευσε ότι εμφανίζονται τα υπάρχοντα βιβλία. Αν ο browser κρατά παλαιό περιεχόμενο, κάνε ανανέωση και έλεγξε ξανά μετά την ενημέρωση του Pages/PWA.

**Σημαντικό:** Το `cloudflare-worker.js` μπορεί να βρίσκεται στο ίδιο δημόσιο repository για να διατηρείς ενιαίο πακέτο· περιέχει *κώδικα μόνο* και **όχι μυστικούς κωδικούς**. Δεν πρέπει ποτέ να βάλεις πραγματικό token/κωδικό μέσα σε αυτό το αρχείο στο GitHub. Η παρουσία του εκεί δεν τον ενεργοποιεί: η εγκατάσταση του Worker γίνεται ξεχωριστά, στο Cloudflare (βήμα 5).

## 4. Δημιουργία GitHub token

1. GitHub → φωτογραφία λογαριασμού → **Settings** → **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**.
2. Δώσε περιγραφικό όνομα, π.χ. `pontian-library-sync`, και εύλογη ημερομηνία λήξης (θα χρειαστεί ανανέωση όταν λήξει).
3. **Repository access → Only select repositories** → διάλεξε **μόνο** το repository της βιβλιοθήκης.
4. **Repository permissions → Contents → Read and write**.
5. Πάτησε δημιουργία και αντέγραψε το token σε ασφαλές, ιδιωτικό μέρος. **Μην το στείλεις σε συνομιλία, μην το ανεβάσεις στο GitHub και μην το βάλεις σε HTML/JS της ιστοσελίδας.**

## 5. Cloudflare Worker — μία φορά

1. Cloudflare dashboard → **Workers & Pages** → **Create** → **Worker** (οι τίτλοι κουμπιών ενδέχεται να διαφέρουν λίγο).
2. Επίλεξε ένα όνομα π.χ. `pontian-library-sync`, δημιούργησέ τον και άνοιξε **Edit code**.
3. Αντικατάστησε **ολόκληρο** τον προεπιλεγμένο κώδικα με το περιεχόμενο του `cloudflare-worker.js` από το ZIP. Πάτησε **Deploy**.
4. Στις **Settings → Variables and Secrets** πρόσθεσε τα παρακάτω **Secrets** (τύπος **Secret**, όχι Text):
   - `ADMIN_PASSWORD` = ένας δικός σου ισχυρός, μοναδικός κωδικός διαχείρισης.
   - `GITHUB_TOKEN` = το token του βήματος 4.
5. Πρόσθεσε τις εξής **Text variables** (τύπος **Text**):
   - `GITHUB_OWNER` = το όνομα χρήστη/οργανισμού που κατέχει το GitHub repository.
   - `GITHUB_REPO` = το **όνομα** του repository, χωρίς `https://`.
   - `GITHUB_BRANCH` = το branch όπου ανέβαζες τις εκδόσεις (π.χ. `main`).
   - `ALLOWED_ORIGIN` = μόνο το **origin** της δημόσιας βιβλιοθήκης, δηλ. `https://username.github.io` για GitHub Pages, **χωρίς** `/repository/` ή τελικό `/`. Για custom domain γράψε το ακριβές `https://domain.example`.
6. Αποθήκευσε/κάνε Deploy τις αλλαγές όπου ζητηθεί. Αντέγραψε την HTTPS διεύθυνση του Worker που καταλήγει σε `.workers.dev`.

**Σημείωση:** Δεν χρειάζεται να ενεργοποιήσεις Cloudflare Access για τον συγκεκριμένο Worker: ο κώδικας απαιτεί δικό του κωδικό για GET/PUT και ελέγχει origin. Ο έλεγχος origin δεν αντικαθιστά τον κωδικό. Μη χρησιμοποιήσεις τον ίδιο κωδικό με άλλες υπηρεσίες.

## 6. Σύνδεση της διαχείρισης

1. Άνοιξε τη δημόσια διεύθυνση της βιβλιοθήκης και πρόσθεσε `/admin.html` στο τέλος της διαδρομής του repository, π.χ. `https://username.github.io/repository/admin.html`.
2. Στο πεδίο **Worker** επικόλλησε την πλήρη διεύθυνση `https://...workers.dev` **χωρίς τελική κάθετο**.
3. Στον **Κωδικό** πληκτρολόγησε το `ADMIN_PASSWORD` του Worker.
4. Πάτησε **Σύνδεση και φόρτωση**. Πρέπει να φορτωθούν τα ήδη δημοσιευμένα βιβλία και λήμματα.
5. Πριν από σημαντικές διορθώσεις επίλεξε **Λήψη αντιγράφου JSON**.
6. Άλλαξε δοκιμαστικά το **έτος έκδοσης** ενός βιβλίου (άφησέ το κενό αν είναι άγνωστο) και πάτησε **Δημοσίευση στο GitHub**.
7. Δες ότι δημιουργήθηκε νέο commit στο **ίδιο branch** και ανανέωσε τη δημόσια βιβλιοθήκη. Οι αλλαγές στο Pages/PWA μπορεί να καθυστερούν λόγω δημοσίευσης ή cache.

Από εδώ και πέρα, η συνήθης διαδικασία είναι **admin.html → αλλαγές → δημοσίευση**. **Δεν ξανανεβάζεις χειροκίνητα το `library-data.json`** για κάθε νέο διήγημα.

## 7. Ασφάλεια και αποφυγή απώλειας περιεχομένου

- Το `admin.html` είναι δημόσια προσβάσιμο ως σελίδα. Η **ανάγνωση μέσω Worker και η εγγραφή στο GitHub** προστατεύονται με κωδικό. Η δημόσια ανάγνωση των ήδη δημοσιευμένων βιβλίων δεν απαιτεί κωδικό.
- Ο Worker συγκρίνει το SHA του αρχείου πριν από εγγραφή. Αν εμφανιστεί **HTTP 409**, έχει αλλάξει το αρχείο στο μεταξύ: σώσε πρώτα αντίγραφο των μη δημοσιευμένων αλλαγών, φόρτωσε ξανά και συμφιλίωσε τις αλλαγές. Μην πιέζεις επανειλημμένα «Δημοσίευση».
- Κάθε επιτυχής δημοσίευση δημιουργεί **GitHub commit**. Το ιστορικό μπορεί να βοηθήσει σε επαναφορά.
- Μην επικολλάς πραγματικούς κωδικούς σε `admin.js`, `index.html`, `README.md` ή `cloudflare-worker.js`.
- Η νέα διαχείριση αποστέλλει το περιεχόμενο του JSON στο GitHub και δεν αποθηκεύει τον κωδικό στο localStorage. Ασφάλισε τον υπολογιστή σου και μην αφήνεις ανοιχτή συνεδρία διαχείρισης σε κοινόχρηστη συσκευή.
- Το `library-data.json` είναι περίπου 3,9 MB: ο Worker το ανακτά από GitHub Blob API, όχι από το ενδεχομένως κενό πεδίο `content` του Contents API για μεγάλα αρχεία.

## 8. Συνήθεις δυσκολίες

- **401**: λάθος `ADMIN_PASSWORD` ή μεταβλητή που δεν αποθηκεύτηκε.
- **403 / CORS**: έλεγξε το `ALLOWED_ORIGIN` (πρωτόκολλο και domain ακριβώς όπως φαίνεται στη γραμμή του browser, χωρίς path).
- **404**: έλεγξε `GITHUB_OWNER`, `GITHUB_REPO`, `GITHUB_BRANCH` και την τοποθεσία `library-data.json` στη ρίζα του repository.
- **409**: υπάρχει νεότερη αλλαγή στο GitHub· ξαναφόρτωσε αφού κρατήσεις πρόχειρο αντίγραφο.
- **Παλαιά έκδοση βιβλιοθήκης**: δοκίμασε επαναφόρτωση και έλεγξε τη λειτουργία PWA/service worker και αν τελείωσε το GitHub Pages deployment.
- **Ληγμένο token**: δημιούργησε νέο περιορισμένο token και αντικατάστησε το Secret `GITHUB_TOKEN` στον Worker.

## 9. Ιστορικό σημαντικών αλλαγών

- **2.1.0**: βασικό ενσωματωμένο admin, Cloudflare Worker/GitHub δημοσίευση, προαιρετικό `publicationYear`.
- **2.0.7**: στο κινητό το double tap του μενού δεν ενεργοποιεί ταυτόχρονα γλωσσάρι· παρατεταμένο άγγιγμα 350 ms.
- **2.0.6**: περιορισμός ενεργοποίησης ξεφυλλίσματος στις εξωτερικές άκρες του desktop για καλύτερη επιλογή κειμένου.
- **2.0.5**: αναγνώριση πολυλεκτικών/σύνθετων λημμάτων και βελτιώσεις αναζήτησης.
- **2.0.4**: ελάχιστη διάρκεια popup 1,5 δευτερόλεπτα.

Η έκδοση δεν έχει επαληθευτεί με πραγματικά διαπιστευτήρια Cloudflare/GitHub ή σε φυσική συσκευή· η τελική δοκιμή είναι το βήμα 6.


## v2.1.3 — Κάρτες βιβλίων, ταξινόμηση και διαχωριστικά

- Κινητό: στενότερο εξώφυλλο και κατάλληλο μέγεθος τίτλου ώστε να μην κόβονται ελληνικές λέξεις στη μέση.
- Αρχική συλλογή: προεπιλεγμένη αλφαβητική ταξινόμηση τίτλων (Α–Ω), επιλογές κατά συγγραφέα (Α–Ω) και έτος έκδοσης (αύξουσα/φθίνουσα σειρά). Βιβλία χωρίς γνωστό έτος εμφανίζονται μετά τα χρονολογημένα.
- Reader: γραμμή TXT με ακριβώς `***` (επιτρέπονται κενά γύρω) αποδίδεται ως κεντραρισμένο διαχωριστικό ενότητας με το υπάρχον στυλ κεντραρίσματος `***`. Δεν δημιουργεί κεφάλαιο. Αστερίσκοι μέσα σε πρόταση μένουν στο κείμενο.
- Δεν αλλάζουν το `library-data.json`, το `admin.html`, ο Worker, οι ρυθμίσεις popups ή οι χειρονομίες. Αλλαγμένα αρχεία: `index.html`, `sw.js`, `README.md`.
- Ελέγχθηκε η σύνταξη των JavaScript blocks· η τελική εμφάνιση χρειάζεται έλεγχο σε πραγματικό κινητό.
